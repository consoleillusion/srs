# Migrations

## Decision

Migrations are generated by comparing the built schema with the recorded
database state. They are deterministic, immutable once applied, and never edited
by hand.

## Rules

- `.migrations/schema-state.json` records the SQL of every table, trigger and
  view created by the migrations.
- New objects are created. Changed tables are rebuilt by copying their surviving
  columns, dropping the old table and renaming the new one.
- Views and triggers are dropped before a table rebuild and recreated last.
- Removed objects are dropped.
- Unchanged schemas produce no new migration.
- Each applied migration is recorded in `__migrations` and is not changed later.
- Startup refuses to serve when schemas no longer match the recorded fingerprint
  in packaged use.

## Consequences

Database changes are reviewable as SQL and repeatable from an empty database.
The test suite applies every migration, so generated SQL is exercised rather
than assumed correct.

See [development.md](../doc/development.md) for commands and failure handling.
